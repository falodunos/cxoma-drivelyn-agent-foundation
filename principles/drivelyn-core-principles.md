# Drivelyn core principles

1. Drivelyn is a lifelong driving-learning system.
2. Drivelyn is not a traffic-law enforcement system.
3. Unsupported telemetry inference must not be presented as fact.
4. Insufficient evidence must remain explicit.
5. Learner-facing scores must be explainable.
6. Backend analysis and review are authoritative for scoring.
7. Active-driving interaction must remain minimal and non-distracting.
8. Never log raw telemetry, tokens or sensitive identity/location data.
9. External provider identity stays separate from the internal Drivelyn learner UUID.
10. Significant engineering changes require reproducible validation and proportionate review.
11. Repository state is authoritative; model memory is optional convenience.
12. Project-specific Codex behavior must be repository-local and portable.

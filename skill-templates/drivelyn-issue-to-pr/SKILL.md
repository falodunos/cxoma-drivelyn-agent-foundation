# Drivelyn issue-to-PR template

Materialize this concept in each consumer with local policy, matrix, plan and command paths. Do not run it from this upstream template as a consumer dependency.

Read task instructions and local AGENTS/shared autonomous policy. Determine autonomous or human-controlled mode before mutations. Validate the issue still applies; inspect evidence, duplicates, repository state and verified base. Choose fast/deep using local criteria. Create a safe dedicated branch only when authorized and existing changes are accounted for; stop on unsafe unrelated dirty state.

Create an execution plan for substantial work. Implement only the bounded issue. Run focused and full repository checks, inspect the diff, self-review, invoke required read-only reviewers from the local matrix, resolve material findings, revalidate and update docs/plan.

Human-controlled: produce scoped commit instructions and STOP without commit/push/PR. Autonomous: inspect staged task files, commit only accepted work, verify push destination and open/update a DRAFT PR using the local template; verify actual GitHub results, report references and STOP before merge. No auto-merge. If external handoff is unavailable, preserve accepted local work and report BLOCKED with executable human handoff instructions and no invented IDs. Reconcile ambiguous writes before retrying.
